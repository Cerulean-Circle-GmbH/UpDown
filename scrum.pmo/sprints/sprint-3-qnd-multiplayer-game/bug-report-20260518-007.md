# Bug Report BR-013: Spectator Can Delete Room While Host Still In It

**Reporter:** McDonges (d1106ed8-8d8b-423f-87b6-f06b2d09a69e)
**Date:** 2026-05-18
**Status:** DONE

## Report
"i was watching a room. then i exited it and it was shown as a finished game. so i deleted it, while the host was still in it to play again. this should not be possible, so there should be still a watch button."

## Problem
1. Spectator leaves a room after game ends
2. Room shows as "finished" in lobby with 🗑 Remove button
3. But the HOST is still in the room (waiting for Play Again)
4. Spectator can delete the room — kicking the host out

## Expected Behavior
- If ANY player is still in the room (host waiting for Play Again), the room should show Watch button, NOT Remove
- Remove button should only appear when the room is truly empty (no players, no host)
- A room with players in "play again" state is NOT finished — it's waiting

## Fix
- Server REMOVE_ROOM handler: reject if room still has connected players
- Client lobby: show Watch button if room has players, even if game state is "finished"
- The "finished" state only means the game round ended, not that the room is abandoned

## Acceptance Criteria
- [ ] Cannot delete a room that still has connected players
- [ ] Room with host in Play Again state shows Watch, not Remove
- [ ] Remove only available for truly empty/abandoned rooms
- [ ] Server rejects REMOVE_ROOM if room.players.size > 0
- [ ] Vitest passes
