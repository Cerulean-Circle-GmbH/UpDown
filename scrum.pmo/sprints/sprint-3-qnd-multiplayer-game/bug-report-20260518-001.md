# Bug Report BR-007: Rework Link Account — Move to Player Popup + Correct Merge Direction

**Reporter:** Anonymous
**Date:** 2026-05-18
**Status:** DONE

## Full Requirement (Tron — complete spec)

### Player Popup UI Changes
- **My own popup:** Download vCard button ONLY (remove Close — redundant)
- **Other player's popup:** Download vCard + **Link Account** button (replace Close)
- **Remove** Link Account / consolidation from under Start Game — moves to player popup only

### Link Account Flow (clicking Link Account on ANOTHER player's popup)
1. I click Link Account on another player's popup
2. **MY UUID stays** — it is the primary identity
3. **MY profile details are PRESERVED** and copied over into the other player's profile
4. The other player becomes a **new device on MY user** — as if I logged in on their device
5. The other player's UUID is **FINALLY DELETED** after merge completes

### Merge Direction (CRITICAL — opposite of current T86 implementation)
Current T86: requester (who clicks) becomes primary, friend absorbed.
**NEW:** MY profile is always primary. The OTHER player I'm linking is absorbed into ME.
- My UUID: KEPT
- My name, avatar, phone, url, stats: KEPT
- Other player's devices: ADDED to my device list
- Other player's stats: MERGED (additive for counts, max for bests)
- Other player's UUID: DELETED (not redirected — fully removed after merge)
- Other player's next connect: gets TOKEN_REDIRECT to my UUID

### No Secret Code Needed
The Link Account button is in the player popup — I can see who I'm linking. No secret code prompt needed. The action is: "merge this player into my account."

### Confirmation
Show confirmation dialog: "Link {otherPlayerName}'s account into yours? Their devices will be added to your profile. This cannot be undone."

## Architect Analysis (2026-05-18)

### Merge direction: ALREADY CORRECT — no reversal needed
Current CONSOLIDATE (server.ts:996): requester=primary, friend absorbed. This matches BR-007. T86 spec said the same. The "reversal" in the bug title is a misunderstanding — current code is right.

### Changes needed (5 items)

**1. CONSOLIDATE message: targetToken instead of secretCode**
Current: `{ type: 'CONSOLIDATE', friendCode: '7294' }` → server loops all profiles matching code.
New: `{ type: 'CONSOLIDATE', targetToken: 'uuid' }` → direct `playerProfiles.get(targetToken)`.
Client has `p.playerToken` for every player (broadcast in `allPlayerInfo`, GameRoom.ts:709).

**2. Delete profile after merge (two-phase)**
Current: `friend.redirectTo = myToken` (kept alive). New: redirect first, saveProfiles, then delete from Map. Keep in-memory `deletedTokenRedirects` Map for the window between delete and other player's reconnect.

**3. Player popup buttons**
My popup: vCard only (remove Close — overlay tap dismisses).
Other popup: vCard + "🔗 Link Account" (replaces Close). Click → `confirm()` dialog → sends `CONSOLIDATE { targetToken: p.playerToken }`.

**4. Remove "Add Friend" from lobby controls**
Delete `add-friend-btn` from renderControls (line 503) and its handler (lines 529-536).

**5. Security: same-room check**
playerToken is broadcast to all players. Without a check, anyone could merge anyone. Add: `roomManager.findPlayerRoom(clientId)` must contain the target player.
