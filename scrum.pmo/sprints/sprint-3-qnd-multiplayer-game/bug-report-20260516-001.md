# Bug Report BR-005: Bug Reports Must Track Reporter UUID + Show Status in Profile

**Reporter:** Anonymous (unknown UUID — this is the problem)
**Date:** 2026-05-16
**Status:** DONE

## Report
"the bug reports have to be clearly tracked back to the reporter uuid and the bug report status needs to be integrated into their profile as the devices"

## Requirements

### 1. Bug report must include reporter UUID
- BUG_REPORT message must always include playerToken (reporter UUID)
- The bug report .md file created by PO must record the UUID
- If reporter is "Anonymous unknown" — that's the bug. The server should resolve the UUID from the WebSocket connection's identified token.

### 2. Bug report status visible on reporter's /profile page
- /profile shows a "My Bug Reports" section (like the devices section)
- Each bug report listed with: date, short description, status (PLANNED/IN PROGRESS/FIXED)
- Data stored in PlayerProfile or linked via reporter UUID

### Server Changes
- BUG_REPORT handler: resolve playerToken from WebSocket connection (same as CONSOLIDATE does)
- Include playerToken in the otmux send prompt: `[@browser-user {name} {uuid}] BUG REPORT: {text}`
- Store bug reports in PlayerProfile.bugReports[] or separate data/bug-reports.json with reporter UUID
- PROFILE response: include bug report list for the requesting player

### /profile Page Changes
- Add "🐛 My Bug Reports" section showing reports filed by this player
- Each entry: date, text preview, status

## Acceptance Criteria
- [ ] Bug report includes reporter UUID (not "unknown")
- [ ] /profile page shows "My Bug Reports" section
- [ ] Bug report status tracked (PLANNED → IN PROGRESS → FIXED)
- [ ] Reporter can see their own bug reports on their profile
- [ ] Vitest passes
