# Bug Report BR-010: Bug Report Lifecycle — Status Not Updating on Profile

**Reporter:** Marcel Donges (d1106ed8-8d8b-423f-87b6-f06b2d09a69e)
**Date:** 2026-05-18
**Status:** DONE

## Report
"on my profile both bug reports are still marked as planned while they are already done. architect the bug report lifecycle as use cases and process and create a spec for the expert and tester"

## Problem
Bug reports on /profile page always show PLANNED status — never updates to IN PROGRESS or FIXED even after the bug is resolved. The status is stored in PlayerProfile.bugReports[] but nothing updates it when PO marks the bug report .md file as DONE.

## Requirement
Architect must spec the full bug report lifecycle as use cases and process:
1. User submits bug report → status: PLANNED
2. PO assigns to expert → status: IN PROGRESS  
3. Expert fixes → status: FIXED
4. How does status propagate from the .md file back to the profile?

## Architect Spec — 2026-05-18

### 1. Bug Report Lifecycle (Use Cases)

```
Actor: Player (submits)
Actor: PO (triages, assigns, verifies)
Actor: Expert (fixes)
Actor: Server (stores, notifies)

UC-BR1: player.submitBugReport → status: PLANNED
  Server stores in profile.bugReports[] with status='PLANNED'
  Server sends prompt to PO pane via otmux

UC-BR2: po.updateBugStatus → status: IN PROGRESS | FIXED | WONTFIX
  PO sends WS message: {type:'UPDATE_BUG_STATUS', playerToken, bugIndex, status}
  Server updates profile.bugReports[index].status
  Server saves profiles.json

UC-BR3: player.viewBugReports → /profile page shows current status
  Profile page renders bugReports[] with color-coded status
  (Already implemented — line 471: green=FIXED, orange=IN PROGRESS, grey=PLANNED)

UC-BR4: po.viewAllBugs → /admin/bugs endpoint
  Server returns all profiles' bugReports aggregated
  Sorted by date, filterable by status
  (OPTIONAL — lower priority)
```

### 2. Status Transition Options — Analysis

| Option | How | Pros | Cons |
|--------|-----|------|------|
| **A: PO WS command** | PO sends `UPDATE_BUG_STATUS` via paired WebSocket | Real-time, reuses existing pairing | PO must have WS connection open |
| **B: REST API** | `POST /api/bug-status` with token+index+status | Works from curl/scripts, no WS needed | Needs auth (admin key) |
| **C: .md file watcher** | Server reads bug-report-*.md status field | Auto-syncs with PO's .md edits | Complex, fragile file parsing, filesystem coupling |
| **D: otmux command** | PO sends shell cmd that hits REST API | Scriptable, fits OOSH workflow | Extra tooling layer |

**Recommended: Option B (REST API)** — simplest, most reliable, scriptable.

- Endpoint: `POST /api/bug-status`
- Auth: admin secret key (from .env or generate on startup)
- Body: `{ adminKey, playerToken, bugIndex, status }`
- Status values: `PLANNED` | `IN PROGRESS` | `FIXED` | `WONTFIX`
- Response: `{ ok: true, updated: { date, text, status } }`

**Why not A:** PO doesn't keep a game WebSocket open. Bug report pairing is for receiving reports, not sending commands back.

**Why not C:** Parsing .md files for status is fragile. The server shouldn't depend on the sprint directory structure. Violates separation of concerns.

**Bonus: D wraps B.** An oosh script `updown bug.update <token> <index> <status>` can call the REST endpoint. Best of both worlds — PO uses CLI, expert can use curl in tests.

### 3. Expert Implementation Spec

#### 3.1: Add REST endpoint `POST /api/bug-status`

In server.ts HTTP handler section (~line 351 area):

```typescript
} else if (req.method === 'POST' && filepath === '/api/bug-status') {
  let body = '';
  req.on('data', chunk => body += chunk);
  req.on('end', () => {
    try {
      const { adminKey, playerToken, bugIndex, status } = JSON.parse(body);
      if (adminKey !== ADMIN_KEY) { res.writeHead(403); res.end('Forbidden'); return; }
      if (!['PLANNED', 'IN PROGRESS', 'FIXED', 'WONTFIX'].includes(status)) {
        res.writeHead(400); res.end('Invalid status'); return;
      }
      const profile = playerProfiles.get(playerToken);
      if (!profile || !profile.bugReports || !profile.bugReports[bugIndex]) {
        res.writeHead(404); res.end('Bug report not found'); return;
      }
      profile.bugReports[bugIndex].status = status;
      saveProfiles();
      res.writeHead(200, { 'Content-Type': 'application/json' });
      res.end(JSON.stringify({ ok: true, updated: profile.bugReports[bugIndex] }));
    } catch { res.writeHead(400); res.end('Bad request'); }
  });
  return;
}
```

#### 3.3: Add `GET /api/bugs` (optional, for PO dashboard)

Returns all bug reports across all profiles:
```typescript
} else if (filepath === '/api/bugs') {
  const allBugs: any[] = [];
  playerProfiles.forEach((p, token) => {
    (p.bugReports || []).forEach((b, i) => {
      allBugs.push({ token: token.slice(0,8), name: p.name, index: i, ...b });
    });
  });
  allBugs.sort((a, b) => new Date(b.date).getTime() - new Date(a.date).getTime());
  res.writeHead(200, { 'Content-Type': 'application/json' });
  res.end(JSON.stringify(allBugs));
  return;
}
```

```
    ↓

    ↓

```
