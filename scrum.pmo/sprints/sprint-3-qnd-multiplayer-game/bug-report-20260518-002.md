## Architect Analysis — 2026-05-18

### Root Cause Confirmed

**The `/bug-report` page never sends IDENTIFY.** PO diagnosis was close but the actual root cause is upstream of the BUG_REPORT handler.

The BUG_REPORT handler (server.ts:1064-1091) is correctly written — line 1070 resolves `reporterToken` from `wsClient.playerToken` or `tokenToClient` map, line 1071 formats the prompt with name+token. The logic is sound.

The problem: the `/bug-report` page (server.ts:351-402) opens a raw WebSocket but on `ws.onopen` (line 380) only sets `connected=true`. It **never sends IDENTIFY** with the playerToken from localStorage.

Without IDENTIFY:
- `wsClient.playerToken` stays `''` (initialized empty at line 635)
- `tokenToClient` map has no entry for this clientId
- Line 1070: resolves to `'unknown'`
- Line 1068: resolves to `'Anonymous'` (client not in any room)

Compare with main game client (line 434):
```javascript
// Main client sends IDENTIFY on welcome:
if(m.type==='welcome'){ws.send(JSON.stringify({type:'IDENTIFY',playerToken:token,...}))}

// Bug report page does NOT:
ws.onopen=function(){connected=true}  // ← MISSING IDENTIFY
```

### Fix (3 lines)

In server.ts ~line 380, change the bug report page's `ws.onopen`:
```javascript
ws.onopen=function(){
  connected=true;
  var token=localStorage.getItem('updown-player-token');
  if(token){ws.send(JSON.stringify({type:'IDENTIFY',playerToken:token,deviceId:localStorage.getItem('updown-device-id')||''}))}
};
```

Also need to wait for server's `welcome` message before sending IDENTIFY (same pattern as main client):
```javascript
ws.onmessage=function(e){
  var m=JSON.parse(e.data);
  if(m.type==='welcome'){
    var token=localStorage.getItem('updown-player-token');
    if(token){ws.send(JSON.stringify({type:'IDENTIFY',playerToken:token,deviceId:localStorage.getItem('updown-device-id')||''}))}
  }
  if(m.type==='BUG_REPORT_OK'){...}
  ...
};
```
