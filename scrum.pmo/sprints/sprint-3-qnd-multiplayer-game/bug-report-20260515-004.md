# Bug Report BR-004: Secret Code Must NOT Enforce Uniqueness

**Reporter:** Anonymous (via browser bug report)
**Date:** 2026-05-15
**Status:** DONE

## Report
"i just changed my code and got code already in use. this is a SECRET code not a unique code... everybody could have the same code but it is SECRET!!!!"

## Tron Clarification
The code is ONLY valid in combination with the user UUID. So it's always unique anyway (UUID + code pair). The code itself does NOT need to be unique across users. Multiple users can have the same 4-digit code — the UUID distinguishes them.

## Root Cause
UPDATE_SECRET_CODE handler (server.ts) rejects codes already used by another profile. This uniqueness check is WRONG — remove it.

## Fix
- server.ts UPDATE_SECRET_CODE handler: REMOVE uniqueness check
- server.ts generateSecretCode(): just generate random 4-digit, no collision retry needed
- CONSOLIDATE handler: lookup by UUID + code combination, not code alone

## Files to Modify
| File | Change |
|------|--------|
| server.ts UPDATE_SECRET_CODE | Remove `const taken = ...some(p => p.secretCode === newCode)` check |
| server.ts generateUniqueCode() | Simplify — no collision check, rename to generateSecretCode() |
| server.ts CONSOLIDATE | Match by code, but if user provides UUID too, use UUID+code combo |

## Acceptance Criteria
- [ ] Any 4-digit code accepted (no "already in use" error)
- [ ] Multiple users CAN have same code
