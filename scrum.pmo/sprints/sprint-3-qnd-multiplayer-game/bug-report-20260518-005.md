# Bug Report BR-011: Link Account Merge — Profile Not Deleted + No Secret Key Verification

**Reporter:** Marcel Donges (d1106ed8-8d8b-423f-87b6-f06b2d09a69e)
**Date:** 2026-05-18
**Status:** DONE

## Report
"i just tried to merge with samsungTablets account. its device is now in my device list but the samsungTablets profile and uuid still exists. i was not asked for samsungTablet secret key to allow the merge. review and fix that with the team cmm4"

## Two Issues

### Issue 1: Merged profile not deleted
After Link Account merge, the target profile (samsungTablet) still exists. BR-007 spec says: "The other player's UUID will be FINALLY DELETED after the merge is completed." The profile should be deleted from the Map (with redirectTo set first for reconnect window).

### Issue 2: No secret key verification before merge
Link Account in player popup merges immediately without asking for the target's secret code. This is a security gap — anyone in the room can merge any other player into their account without consent. The target's secret code should be required as consent verification.

## Architect Analysis — 2026-05-18

### Code Audit

#### CONSOLIDATE handler (server.ts:1048-1096)
The handler correctly:
- Validates myToken, targetToken, same-room check (lines 1049-1064)
- Merges stats additively, bests by max/min (lines 1069-1077)
- Merges devices with dedup (lines 1080-1084)
- Records consolidatedFrom (line 1087)

**Bug 1 — Delete order wrong (lines 1089-1092):**
```typescript
friend.redirectTo = myToken;   // line 1090: set redirect
saveProfiles();                // line 1091: saves WITH redirectTo to disk
playerProfiles.delete(targetToken); // line 1092: removes from in-memory Map
```
Problem: `saveProfiles()` writes the target profile to disk (with `redirectTo`), then `delete` removes it from the Map. But the saved file still has it. On next server restart, `loadProfiles()` loads it back. Meanwhile, if the target reconnects BEFORE restart, the profile is gone from the Map so no redirect fires.

Fix: save AFTER delete. But then the redirect stub is lost from disk. The correct approach: keep the redirect stub in the Map (don't delete), just mark it as merged. Filter it from views like the leaderboard already does (line 308: `!p.redirectTo`).

**Bug 2 — No secret code verification (MultiplayerUI.ts:453-458):**
```typescript
// Current: just a confirm() dialog — no secret code input
if (targetToken && confirm(`Link ${targetName}'s account into yours?...`)) {
  this.client.send({ type: MSG.CONSOLIDATE, targetToken });
}
```
No `secretCode` field in the CONSOLIDATE message. Server doesn't check it.

### Fix Spec

#### Fix 1: Secret code verification (security)

**Client (MultiplayerUI.ts ~line 453):**
Replace `confirm()` with `prompt()` for secret code:
```typescript
document.getElementById('link-account-btn')?.addEventListener('click', () => {
  const targetToken = (document.getElementById('link-account-btn') as HTMLElement).dataset.token;
  const targetName = (document.getElementById('link-account-btn') as HTMLElement).dataset.name;
  const code = prompt(`Enter ${targetName}'s secret code to link accounts.\nThe code is a 4-digit number shown on their /profile page.\nThis cannot be undone.`);
  if (code && targetToken) {
    this.client.send({ type: MSG.CONSOLIDATE, targetToken, secretCode: code.trim() });
    profileEl.style.display = 'none';
  }
});
```

**Server (server.ts ~line 1053, add after targetToken validation):**
```typescript
const secretCode = msg.secretCode;
if (!secretCode) { send({ type: MSG.CONSOLIDATE_FAILED, reason: 'Secret code required' }); break; }
// ... after friend profile resolved (line 1064):
if (friend.secretCode !== secretCode) {
  send({ type: MSG.CONSOLIDATE_FAILED, reason: 'Wrong secret code' });
  addLog(`🔒 Link account REJECTED: ${myToken.slice(0,8)} → ${targetToken.slice(0,8)} (wrong code)`);
  break;
}
```

#### Fix 2: Profile redirect (not delete)

**Server (server.ts lines 1089-1092), replace with:**
```typescript
// Mark target as redirected — DO NOT delete from Map
// The profile stays in Map+disk as a redirect stub
// Views (leaderboard, room list) filter by !p.redirectTo
friend.redirectTo = myToken;
// Clear sensitive data from the stub
friend.devices = [];
friend.secretCode = '';
friend.bugReports = [];
saveProfiles();
// DO NOT: playerProfiles.delete(targetToken);
// The stub stays so reconnecting target gets TOKEN_REDIRECT
```

This way:
1. Target reconnects (even before restart) → IDENTIFY finds profile → `redirectTo` set → sends `TOKEN_REDIRECT` → client updates localStorage
2. Leaderboard already filters `!p.redirectTo` (lines 308, 1032)
3. Profile page renders the stub but it has no data (devices/bugs cleared)

#### MessageTypes update

No new message type needed. CONSOLIDATE message just adds `secretCode` field:
```typescript
// CONSOLIDATE: { type, targetToken, secretCode }
```
