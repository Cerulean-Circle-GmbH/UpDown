# Bug Report BR-012: Host Elimination Still Ends Game Prematurely (Regression?)

**Reporter:** Hannes (a6d1d577)
**Date:** 2026-05-18
**Status:** DONE

## Report
"I was in a game and was the host, when I lost the game ended even when the other players were playing correctly."

## Context
This is the SAME issue as T83 (host elimination premature end) which was marked DONE. Either:
1. T83 fix regressed during later changes
2. T83 fix didn't cover all code paths (e.g. countdown ON vs OFF)
3. The fix only works when countdown is OFF but not when ON

T83 fix was: auto-enable countdown when host eliminated + spectator view. But Hannes may have been playing with countdown ON — in which case the auto-enable logic wouldn't trigger and a different code path may end the game.

## Architect Analysis — 2026-05-18

### Code Audit: T83 fix trace

**T83 fix (GameRoom.ts:562-567):**
```typescript
const hostPlayer = this.players.get(this.hostId);
if (hostPlayer && !hostPlayer.alive && !this.countdownEnabled) {
  this.countdownEnabled = true;
  this.broadcast({ type: MSG.COUNTDOWN_SETTING, countdownEnabled: true });
}
```
This ONLY fires when countdown is OFF. If countdown is already ON, the condition `!this.countdownEnabled` is false — the fix does nothing. That's intentional: with countdown ON, the game auto-advances anyway (line 595-603).

### Traced code paths for host elimination

**Path A: Countdown ON (Hannes's likely scenario)**
1. `resolveRound()` → host `alive = false` (line 545)
2. T83 fix skipped (countdown already ON)
3. Line 582: `alivePlayers.length > 0` → no endGame
4. Line 595-603: exchange 3s → `nextRound()`
5. **Game continues.** ✅

**Path B: Countdown OFF**
1. `resolveRound()` → host `alive = false`
2. T83 fix triggers → countdown turns ON
3. Line 582: `alivePlayers.length > 0` → no endGame
4. Line 595-603: (now countdown ON) → exchange → nextRound
5. **Game continues.** ✅

**Both paths work.** The T83 fix is correct. No regression from BR-007 or T91 (those didn't touch resolveRound or elimination logic).

### Bug NOT found in the server — possible explanations

**Explanation 1: All players lost the same round.**
If host AND all others guessed wrong simultaneously → `alivePlayers.length === 0` → `endGame()`. Hannes may have thought others were "playing correctly" but they weren't — all eliminated in the same round. This is correct game behavior (UC-GE1).

**Explanation 2: Missing host transfer on elimination.**
`hostId` is NOT reassigned when the host is eliminated — only on disconnect (removePlayer at line 296). With countdown ON this doesn't matter (auto-advance). With countdown OFF after T83 fix, countdown turns ON so it also doesn't matter. But there's a subtle issue:

**Found: hostId not transferred on elimination (server.ts:887).**
`FORCE_NEXT_ROUND` requires `room.hostId === clientId`. After host elimination, `hostId` still points to the dead host. If countdown is toggled OFF after the host dies (by... nobody — the dead host can't toggle it), this would be a problem. But nobody can toggle it because only the host can, and the host is dead. So this is a theoretical issue, not Hannes's bug.

**Explanation 3: Client confusion.**
The eliminated host sees "💀 Eliminated!" and "👁️ Eliminated — watching remaining players..." This might feel like "the game ended" from the eliminated player's perspective, even though the server continues. The game IS over for THEM, not for the room.

### Verdict

**No server regression found.** The T83 fix works correctly for both countdown ON and OFF. The most likely explanation is that all players lost simultaneously (UC-GE1: game.end.allEliminated), which is correct behavior.

### Recommended action

1. **No code fix needed** — server logic is correct
2. **UX improvement** (optional): When eliminated, show a clearer message: "You're eliminated! The game continues for X remaining players. Watching as spectator..." instead of just "Eliminated — watching remaining players..."
3. **Add hostId transfer on elimination** (low priority, defense-in-depth): In resolveRound(), after applying results, if host is now dead and other humans are alive, transfer hostId. This prevents a theoretical edge case if countdown is somehow disabled while host is dead.

```typescript
// After line 567 (T83 fix), add:
if (hostPlayer && !hostPlayer.alive) {
  const nextAliveHuman = [...this.players.values()].find(
    p => p.alive && !this.bots.has(p.id) && p.id !== this.hostId
  );
  if (nextAliveHuman) {
    this.hostId = nextAliveHuman.id;
    this.broadcast({ type: MSG.HOST_CHANGED, hostId: this.hostId });
  }
}
```
